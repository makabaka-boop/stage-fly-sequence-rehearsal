# 吊杆口令预演台

纯前端的舞台吊杆口令预演工具：把一叠口令卡拖放排序后，系统从**空载且归位**的初始状态逐卡推演，遇到第一张非法卡即停止，并给出首错位置、具体原因与当时的吊杆状态。无任何业务后端，不访问在线服务。

技术栈：React 18 + TypeScript + Vite；Vitest 验证裁决规则与走台会话；Playwright 覆盖拖放重排后的复算与逐张走台。

## 口令卡含义

| 口令卡 | 前置条件 | 执行效果 |
| ------ | -------- | -------- |
| 装载 | 空载；重量为 1–500 千克的整数 | 吊杆载重 N 千克（归位、未锁定） |
| 锁定 | 已装载且未锁定 | 吊杆锁定 |
| 移动 | 已锁定且在归位 | 移动到舞台位 |
| 归位 | 在舞台位 | 返回归位 |
| 解锁 | 已锁定且已归位 | 解除锁定 |
| 卸载 | 已装载、未锁定，且本次装载已完成过「锁定→解锁」 | 卸空，回到空载归位的初始状态 |

标准闭环：**装载 → 锁定 → 移动 → 归位 → 解锁 → 卸载**，执行完回到空载归位。

> 装载后只能锁定：装载后直接卸载会被判为首错，必须先锁定再解锁才能卸载（装载与解锁后的物理状态相同，系统以「本次装载是否完成过锁定→解锁」区分二者）。

## 裁决规则

- 从初始状态（空载 · 归位 · 未锁定）按序列逐卡推演。
- **首错即停**：遇到第一张非法卡，该卡不改变状态，后续卡片一律标记「跳过」且不再生效。
- 界面保留首错前的完整轨迹、高亮首错卡并给出具体原因（如「未锁定先移动」「未归位先解锁」「装载重量必须为 1–500 千克的整数」）。
- 结论由卡片序列实时派生：**任何增删、改重量或拖放重排都会清除旧结论并重新裁决**，不存在过期结果。
- 三种结论：**闭合**（全部合法且回到空载归位）、**首错**（唯一定位第一张非法卡）、**未闭合**（全部合法但停在中途状态）。

## 走台会话（逐张报令）

纸面预演之外，监督可以把整理好的序列转成逐张报令的走台会话，让操作者只看到当前应执行的口令、执行后的吊杆状态与剩余张数，而不是一次读完整条轨迹：

- **开始走台**：任意非空序列均可开始，系统复制当时的卡序与重量作为**会话快照**（之后的牌面改动不影响本次会话），吊杆从空载归位的初始状态待命执行。空序列点击时留在待命并给出可理解的反馈。
- **执行下一张**：每次点击通过现有单卡裁决推进游标，面板呈现当前口令、执行后的吊杆状态与「已执行 / 共 N 张 · 剩余 M 张」的进度。
- **完成、未闭合与受阻**：全部口令合法执行**且吊杆回到空载归位**才显示走台完成；全部合法但未归位则显示走台未闭合（终态，可整理序列后重新走台）；遇到非法卡则**停在执行前状态**，给出受阻卡号与原因。重复点击不会越过末张或受阻卡。
- **编辑锁定**：走台进行中收起整套口令序列，锁定牌库与草稿操作，轨迹与实时结论也不再展示——操作者只看到当前口令与进度；会话结束后恢复序列、编辑入口与实时裁决视图。
- 会话状态（待命 / 进行中 / 完成 / 受阻 / 未闭合）由 `src/domain/session.ts` 的纯函数管理，仅存于内存：刷新页面仍按现有空序列启动，回到待命。

## 本地排练草稿（单槽位）

操作区提供「保存草稿 / 恢复草稿」，用于反复试改后找回最后确认的编排：

- **保存草稿**：完成增删、重量修改或拖放后点击，应用先逐卡校验当前序列，再把动作卡（含作为稳定标识的卡片 id）与保存时间写入浏览器 `localStorage`，单槽位覆盖写，并显示保存时间与卡片数。序列不满足契约时（如装载重量越界，实时裁决已判首错）保存被拒绝并给出失败反馈，**不会写入或覆盖槽位中已有的合法草稿**。
- **恢复草稿**：随时（包括刷新页面后）重新读取并**逐卡校验**，通过后整套序列**原子替换**并立即走现有裁决链生成结论、状态面板与轨迹；保存的卡片顺序与装载重量保持不变。
- **损坏/不兼容**：草稿为带 `version` 字段的 JSON 结构，读取时逐卡校验类型、标识与载荷（复用重量边界 1–500 千克整数）。遇到 JSON 损坏、版本不兼容或卡片不合法时，**保留屏幕上的当前序列**，仅在操作区说明无法恢复，异常不会穿透到页面；重新保存可修复槽位。
- 保存成功、恢复成功、操作失败为一组约 4 秒的短暂反馈；草稿不参与实时裁决，未保存用户的拖放复算流程完全不变，应用始终以空序列启动（刷新不自动恢复）。

## 启动方式（Docker Compose）

```bash
# 启动预演台，默认 http://localhost:8080
docker compose up --build web

# 用 WEB_PORT 覆盖宿主端口，例如 http://localhost:9000
WEB_PORT=9000 docker compose up --build web

# 一次性验收：构建后运行 Vitest + Playwright，结束即退出，退出码即验收结果
docker compose run --rm verify
```

`web` 服务为 nginx 托管的纯静态站点；`verify` 服务基于 Playwright 官方镜像，自带浏览器，独立构建并测试，不依赖 `web` 运行。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器
npm run test       # Vitest 裁决规则测试
npm run test:e2e   # Playwright 端到端测试（首次需 npx playwright install chromium）
npm run verify     # 构建 + 单元测试 + 端到端测试
```

## 项目结构

```
src/domain/       状态机与裁决（types / machine / cards / describe），纯函数、无 UI 依赖
                  draft.ts 为单槽位本地排练草稿：版本化 JSON 契约、逐卡校验、localStorage 读写
                  session.ts 为走台会话：快照 / 游标 / 吊杆状态与待命、进行中、完成、受阻的纯函数推进
src/components/   牌库、可拖放序列、裁决横幅、状态面板、推演轨迹、草稿操作区、走台面板
src/domain/__tests__/machine.test.ts   Vitest 裁决规则
src/domain/__tests__/draft.test.ts     Vitest 草稿契约与存储读写
src/domain/__tests__/session.test.ts   Vitest 走台会话：合法推进、首错停步、末张幂等
e2e/reorder.spec.ts                    Playwright 拖放重排复算
e2e/draft.spec.ts                      Playwright 草稿保存/恢复/损坏防护/刷新持久化
e2e/walkthrough.spec.ts                Playwright 逐张走台、受阻停步与编辑锁定/恢复
Dockerfile        多阶段：deps → build → web（nginx）/ verify（Playwright 镜像）
docker-compose.yml                     web 服务（WEB_PORT 覆盖端口）+ verify 一次性验收
```
